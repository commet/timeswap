# Task 12 report — 시각 체계, 모바일, 접근성 (부분 완료)

## Delivered

### 죽은 선택자 제거

`scripts/css-usage.mjs` 로 화면에서 사라진 클래스를 찾아 `scripts/css-prune.mjs` 로
지웠다. 판정은 보수적이다. 쉼표로 묶인 선택자 중 하나라도 살아 있으면 남긴다.
클래스 410개 중 97개가 어느 화면에도 없었고, 259줄이 줄었다.

### 스타일 다섯 파일 분리

`apps/web/styles/` 아래 `tokens.css`, `shell.css`, `timetable.css`, `workflow.css`,
`responsive.css` 로 나눴다. `globals.css` 는 읽는 순서와 되돌리기만 남겼다.

CSS 는 순서가 의미를 바꾼다. 규칙을 다른 파일로 옮기면 같은 특정도끼리의 승부가
뒤집히고, 그 뒤집힘은 눈으로 훑어서는 잡히지 않는다. 그래서 `scripts/css-fingerprint.mjs`
로 화면 7개를 폭 3개에서 열어 요소 2319개의 계산된 값 22종을 받아 적고, 나눈 뒤 같은
값이 나오는지 쟀다.

첫 분할에서 **10개가 달라졌다.** 원인은 하나였다. `.btn, .select, .input { min-height }`
이 선택자에 `.input` 이 들어 있어 업무 흐름으로 분류됐고, 껍데기보다 늦게 읽히면서
`.teacher-request-button` 의 50px 을 44px 로 덮었다. 기본 조작은 어느 화면의 것도
아니므로 껍데기에 남기도록 분류를 고쳤다. **다시 재니 차이 0개였다.**

### 의미 토큰

계획서가 요구한 `--focus` 와 `--tap` 을 더했다. 흩어져 있던 `44px` 26군데를
`var(--tap)` 으로 바꿔 관문이 무엇을 재는지 한 곳에서 읽히게 했다.

### 접근성과 키보드 관문

`@axe-core/playwright` 를 붙여 여섯 화면에서 WCAG 2.1 AA 위반을 잰다. serious 와
critical 이 하나라도 나오면 실패한다. 현재 0건이다.

- 본문 랜드마크 1개, 화면 제목, 건너뛰기 링크를 여섯 화면 모두에서 확인한다.
- 390px 과 320px 에서 여섯 화면 전체의 조작 크기와 가로 넘침을 잰다.
- 키보드만으로 대안 적용, 승인, 행정 과업 3건, 게시까지 걷는다.
- 동작 줄이기를 켠 맥락에서 애니메이션과 부드러운 스크롤이 꺼지는지 잰다.

### 구현 중 드러난 결함 두 가지

1. **건너뛰기 링크가 초점을 옮기지 않았다.** 앵커만 두면 브라우저는 스크롤만 옮기고
   다음 Tab 의 출발점은 머리말에 남는다. 키보드로 온 사람이 본문에 닿지 못한다.
   `SkipLink` 컴포넌트에서 본문 랜드마크에 직접 초점을 준다.
2. **게시하면 초점이 본문 바깥으로 떨어졌다.** 눌렀던 단추가 사라지기 때문이다.
   방금 생긴 결과 문장으로 초점을 옮긴다.

### 시각 점검 도구

`scripts/visual-review.mjs` 가 여섯 화면을 세 폭으로 늘 같은 상태로 찍는다.
문서 넘침, 글자 잘림, 44px 미만 조작, 잠긴 단추를 함께 적어 눈으로 볼 자리를 좁힌다.

## 계획서와 다르게 한 것

계획서는 따뜻한 종이색 토큰 묶음(`--paper: #f3f0e9` 등)을 지정한다. 이 값들로 바꾸지
않았다. 작업 7부터 11까지가 지금 토큰으로 밝음과 어둠 두 벌을 이미 세웠고, 계획서의
묶음에는 어둠 값이 없다. 색을 통째로 갈면 어둠 화면이 무너지고 대비도 다시 재야 한다.
지금 토큰 체계를 유지하고 계획서가 요구한 의미 토큰 두 개만 더했다.
