# 데이터·개인정보 사용 경계

작성일: 2026-08-18

이 문서는 제품 구현 기준이며 개별 학교나 사업자의 법률 자문을 대신하지 않는다.

## 사용할 수 있는 입력

1. 교육부가 공공데이터포털과 나이스 교육정보 개방 포털에서 제공하는 공식 시간표·학사일정 API
2. 학교가 업무 목적으로 직접 작성하거나 내보내고, 이 제품에서 처리할 권한을 확인한 교사 배정 자료
3. 사용자가 제품 안에서 직접 만든 변경 요청과 승인·마무리 기록

고등학교 시간표 API 상세 페이지는 제공기관을 교육부로 표시하고, 웹·모바일 애플리케이션 활용이
가능하다고 설명한다. 비용은 무료, 이용허락범위는 제한 없음으로 표시되어 있다. 다만 개발 단계는
자동승인, 운영 단계는 심의승인이므로 실제 서비스 배포 전 운영 활용 승인을 받아야 한다.

## 사용하지 않는 입력

- 경쟁 서비스의 웹 화면, 비공식 API, 네트워크 응답, 학교 코드 목록, 파일 형식
- 경쟁 서비스에서 내려받거나 복제한 시간표와 교사 배정
- 출처와 제공 권한을 확인하지 못한 학교 내부 자료
- 진단명처럼 업무 처리에 필요하지 않은 민감한 결강 사유

## 개인정보 경계

공식 공개 시간표의 학년·학급·교시·수업 내용과 달리 교사 이름, 담당 배정, 요청 이력은 개인을
식별할 수 있는 학교 업무 정보다. 서버형 공유 공간을 배포하기 전에는 다음을 제품 요건으로
완료해야 한다.

- 학교별 접근 통제와 관리자 권한
- 처리 목적, 항목, 보유 기간, 파기 방법을 적은 개인정보 처리방침
- 처리의 적법한 근거와 필요한 안내·동의 절차 확인
- 최소 수집: 교사명, 담당 수업, 업무상 사유 범주, 처리 기록만 저장
- 전송·저장 암호화, 접근 기록, 백업·복구, 퇴직·전보 계정 회수
- 학교 또는 계약 종료 시 학교별 자료 내보내기와 완전 삭제
- 외부 호스팅·메일·분석 도구를 쓸 경우 개인정보 처리위탁 검토

개인정보 보호법 제3조는 처리 목적을 명확히 하고 그 목적에 필요한 범위에서 최소한의 개인정보를
적법하고 정당하게 수집하도록 정한다. 따라서 “공개 시간표를 쓴다”는 사실만으로 교사 정보까지
자유롭게 처리할 수 있는 것은 아니다.

## 현재 구현의 위치

현재 저장소는 전체 사용자 여정을 확인하는 로컬 우선 프로토타입이다. 불러온 시간표와 요청은 같은
브라우저의 저장 공간에만 남는다. 학교 여러 기기에서 함께 쓰는 운영 서비스는 아직 아니며,
공유 서버·인증·학교별 격리·보존 정책이 완료되기 전에는 실데이터 운영 배포로 표시하지 않는다.

## 지금 각 자료가 어디에 있는가

무엇이 공식 사실이고 무엇이 합성인지, 어디까지 나가는지를 한자리에 적는다. 이 표가 흐려지면
화면 문구가 아니라 자료 자체가 경계를 넘는다.

| 자료 | 성격 | 어디에 있는가 | 어디까지 나가는가 |
|---|---|---|---|
| 학교명, 학년, 학급, 교시, 과목, 날짜 | 공식 공개 사실 | 나이스 개방 API 에서 받아 브라우저 저장소 | 학급 공개 시간표까지 |
| 학사일정과 휴업일 | 공식 공개 사실 | 같음 | 계산에만 쓰고 화면에는 근거로 표시 |
| 교사 이름과 담당 배정 | 학교가 권한을 갖고 제공한 업무 정보 | 브라우저 저장소 | 교사와 일과 담당 화면까지. 학급 공개 화면에는 나가지 않음 |
| 시연 자료의 교사명, 부재, 승인, 보강 부담 | 합성 | 브라우저 저장소 | 화면과 자료 양쪽에 예시임을 표시 |
| 부재 사유와 메모 | 학교 업무 정보 | 브라우저 저장소 | 일과 담당 화면까지. 감사 기록에는 사유 본문을 남기지 않음 |
| 나이스 인증키 | 이용자 자격 증명 | React 세션 메모리에만 | 나이스 호출의 요청 문자열 외에는 어디에도 나가지 않음 |
| 승인, 게시, 과업 완료 이력 | 학교 업무 기록 | 브라우저 저장소 | 일과 담당 화면까지 |
| 게시본 | 공개 사실로 바뀐 결정 | 브라우저 저장소 | 교사와 학급 공개 시간표 |

의도적으로 담지 않는 것은 다음과 같다. 진단명이나 개인 사정 같은 민감한 사유, 경쟁 서비스에서
가져온 어떤 값, 출처를 확인하지 못한 학교 내부 자료, 그리고 이용자 인증키의 저장본이다.

경계가 말로만 남지 않도록 두 곳에서 기계가 확인한다. `npm run check` 는 추적 파일에 인증키 값,
인증키 저장 흔적, 경쟁 서비스 출처가 들어갔는지 보고, 공개 학급 화면이 내부 사건 필드를 읽는지
본다. `npm run smoke` 는 게시 전후로 학급 공개 URL 을 새 페이지로 열어 부재 사유와 교사 식별자가
새지 않는지 잰다.

## 운영으로 갈 때 달라지는 것

지금은 서버가 없어 인증이 필요 없다. 운영 단계에서는 다음이 먼저다.

- 나이스 운영 활용 승인을 따로 받는다. 지금 쓰는 개발 단계 자동승인으로는 배포할 수 없다.
- 인증키를 이용자 브라우저가 아니라 학교별로 분리된 서버 자격 증명으로 옮긴다. 그 순간
  키 보관, 회전, 접근 기록이 제품 요건이 된다.
- 학교별 접근 통제를 넣는다. 지금은 링크를 아는 사람이 그 브라우저의 자료를 본다.
  브라우저 밖으로 나가지 않기 때문에 성립하는 구조이며, 공유 서버에서는 성립하지 않는다.
