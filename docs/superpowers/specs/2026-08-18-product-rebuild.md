# 조율 제품 재구축 설계

## 목표

교사는 별도 계정이나 나이스 인증키 없이 자신의 시간표를 먼저 보고, 결강 수업을 골라
비교 가능한 교체안을 요청한다. 일과 담당자는 같은 학교의 요청을 검토하고 승인·반려·공지·
행정 반영까지 한 흐름으로 끝낸다.

## 데이터 원칙

- 시간표 원본은 나이스 교육정보 개방 API와 학교가 권한을 갖고 제공한 자료만 사용한다.
- 다른 상용 서비스의 데이터, 비공식 API, 학교 코드, 파일 형식, 화면 표현을 사용하거나
  호환하지 않는다.
- 교사명과 담당 배정, 요청 이력은 학교별로 격리되는 최소 정보로 다룬다.
- 결강 사유는 건강 상태가 드러나는 상세 문장 대신 업무상 부재, 연수·출장, 기타처럼
  업무 처리에 필요한 범주만 저장한다.
- 현재 릴리스는 브라우저 안의 데모 학교 공간으로 전체 여정을 검증한다. 서버 연동은
  동일한 도메인 모델을 교체할 수 있는 저장소 경계 뒤에 둔다.

## 사용자와 핵심 여정

### 교사

1. 개인 링크 또는 기억된 기기로 자신의 오늘 시간표를 바로 본다.
2. 변경 요청을 누르고 날짜와 결강 수업을 고른다.
3. 후보를 한 표에서 변경 수, 협조 교사, 학생 영향, 추천 이유로 비교한다.
4. 시간표 미리보기를 확인하고 요청을 보낸다.
5. 검토 중·승인·반려 상태와 최종 시간표를 확인하고 필요하면 요청을 취소한다.

### 일과 담당

1. 요청함에서 날짜와 긴급도, 처리 상태를 본다.
2. 요청의 원안과 후보를 비교하고 필요하면 다른 후보를 고른다.
3. 승인 또는 반려하고 행정 반영 체크리스트를 끝낸다.
4. 나이스 입력 목록, 교사 공지, 결재용 문서를 만든 뒤 게시한다.

## 정보 구조

- 시작: 실제 사용 시작과 샘플 체험을 분리한 간결한 랜딩
- 교사 홈: 오늘 시간표, 이번 주, 요청 상태
- 변경 요청: 수업 선택, 후보 비교, 시간표 미리보기, 제출 확인
- 일과 담당: 요청함, 요청 상세, 행정 마무리
- 학교 설정: 공개 시간표 출처, 교사 배정, 개인 링크, 자료 상태

## 시각 방향

- 주제: 한국 중고등학교의 주간 시간표와 일과 운영
- 단일 작업: 시간표를 읽고 변경을 끝내는 것
- 색: porcelain #F4F6FA, ink #172033, indigo #4456C7, coral #E45D4F,
  teal #168A78, mist #E7EAF2
- 글꼴: Pretendard를 본문·제목에 쓰되 숫자와 시간은 tabular figures로 정렬한다.
- 레이아웃: 시간표가 화면의 중심이고, 작업 단계는 오른쪽 레일 또는 모바일 하단 시트로 붙는다.
- 시그니처: 선택한 수업에서 후보의 이동 경로가 시간표 위에 이어지는 교체 경로 표현.
- 카드가 페이지 구조를 대신하지 않게 하고, 표·행·분할선으로 비교와 행정 흐름을 표현한다.

## 완료 기준

- 데스크톱 1360px와 모바일 390px에서 교사와 일과 담당 전체 흐름이 끊기지 않는다.
- 후보 설명과 버튼을 카드마다 반복하지 않고 비교 후 한 번만 행동한다.
- 오늘 시간표가 모바일 첫 화면에 보인다.
- 모든 변경 요청에 날짜와 상태가 있다.
- 키보드만으로 주요 여정을 수행할 수 있고 44px 미만의 주요 터치 대상이 없다.
- 경쟁 서비스와 비공식 연동 관련 현재 문서 흔적이 제거된다.
- 설정 검사, 타입 검사, 단위 테스트, 빌드, 브라우저 스모크가 통과한다.
