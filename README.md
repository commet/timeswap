# 조율

학기 중 수업 교체를 찾아 주는 도구. `timeswap` 은 저장소 이름으로만 남은 가칭이다.

교사 출장과 연수 등으로 수업 변경이 필요할 때 가능한 교체와 보강을 비교하고,
교사의 요청부터 일과 담당자의 승인·행정 마무리까지 한 기록으로 잇는다.

이름은 `apps/web/lib/brand.ts` 한 곳에서 정한다. 화면, 문서 제목, 인쇄물이 모두 그 값을 읽는다.

## 지금 되는 것

- 모바일은 오늘 수업, 데스크톱은 주간 시간표에서 바로 시작
- 결강 수업을 누르면 맞바꾸기, 연쇄 교체, 빈 시간 옮기기 후보를 전수 탐색해 순위로 제시
- 후보는 카드 나열이 아니라 협조 교사·변경 수·영향을 비교하는 행으로 표시
- 상위 5개를 먼저 보여 주고 나머지 후보는 필요할 때 펼치기
- 선택한 안의 경로와 근거를 확인한 뒤 한 번만 요청
- 요청의 검토 중·승인·반려·게시 완료 상태와 취소 기능
- 일과 요청함에서 승인·반려하고, 나이스 입력·공지·결재 문서를 마쳐야 게시
- 교체가 어려운 수업은 보강 후보도 같은 비교·요청·승인 흐름으로 처리
- 분반과 이동수업, 복수교사, 합반을 하나의 묶음으로 다뤄 통째로 교체
- 나이스 자료에 없는 이동수업 표시를 물리적으로 확실한 경우는 자동으로 묶고, 애매하면 여쭤보고 묶기
- 나이스 학사일정의 휴업일을 이번 주 요일로 옮겨 그날로 가는 안을 아예 빼기
- 정기고사나 학교 행사처럼 학사일정에 없는 날은 요일 단추로 직접 지정
- 수요일 단축수업처럼 요일마다 교시 수가 다르면 없는 교시로 옮기지 않기
- 같은 이름이 같은 교시에 두 과목을 맡고 있으면 동명이인으로 보고 알림
- 하루 결근 대기열, 요일 통째 결강, 근무 불가 시간 잠금
- 시간강사처럼 근무 요일이 갈리는 경우 요일 단추 하나로 잠금
- 승인된 안만 시간표에 반영하고 행정 마무리 전에는 게시할 수 없도록 상태 전이 제한
- 요청별 변경 공지와 나이스 입력 목록 복사
- 결재용 교체 계획서 인쇄. 신청 교사와 사유, 변경 표, 협조 교사 확인란까지
- 교체가 없을 때 보강 후보를 같은 과목, 그날 부담, 최근 협조 횟수로 순위 매겨 제시
- 선택과목이 많은 학년을 과목 다양성으로 알아내 교체가 어려운 이유를 미리 설명
- 특성화고에서는 그 이유가 다르므로 전문교과 몫을 보고 다른 문장으로 설명
- 전문교과 실습(과목명 앞 별표)을 알아보고, 그 보강은 실습을 맡는 분을 먼저 제시
- 실습처럼 여러 교시가 이어진 수업은 한 교시만 떼어 내는 안을 뒤로 밀기
- 한 칸에 과목이 둘인 편성(예술 계열 전공 실기)을 둘 다 살려 한 묶음으로 처리
- 이동수업은 교체가 거의 성립하지 않아, 묶음 수업에서는 보강 후보를 함께 제시
- 보강도 승인 후 정식 변경으로 반영하고 결재 계획서와 나이스 목록에 기록
- 나이스 교육정보 개방 포털에서 학교를 찾아 학급 시간표와 학사일정을 직접 불러오기
- 교사 배정은 같은 학년 같은 과목을 한 번에 채우고, 채운 결과는 파일로 동료와 나누기
- 배정을 다 채우지 않아도 안전. 담당을 모르는 자리는 수업이 있는 것으로 보고 비켜 감
- 협조 균형: 이미 도와준 교사는 다음 추천에서 뒤로 밀림

## 자료 취급 원칙

1. 외부 상용 서비스의 데이터, 코드, 내부 형식, 비공식 API를 사용하지 않는다.
2. 입력은 공식 개방 자료이거나 학교가 처리 권한을 가진 자체 자료만 받는다.
3. 시간표는 이용자 브라우저에만 둔다. 우리 서버는 없다.
4. 나이스 호출은 이용자 브라우저가 직접 하고, 인증키도 이용자 것을 쓴다.

현재 요청함은 한 브라우저 안에서 전체 여정을 검증하는 로컬 프로토타입이다. 학교 여러 기기의
실데이터를 연결하는 운영 서비스가 아니다. 서버형 공유 공간은 인증, 학교별 격리, 보유·파기 정책을
완료한 뒤 별도 단계로 제공한다. 자세한 기준은 [데이터·개인정보 사용 경계](docs/data-and-privacy-boundary.md)에 있다.

## 구조

```
packages/engine   프레임워크에 매이지 않는 탐색 엔진 (TypeScript)
  src/units.ts      묶음 단위 정의와 하드 제약 검사
  src/search.ts     전수 탐색: 이동, 2자 맞바꾸기, 3자 연쇄
  src/score.ts      소프트 점수와 근거 트레이스
  src/cover.ts      교체가 없을 때의 보강 후보와 순위 근거
  src/synthetic.ts  구성적 학교 생성기 (이분 그래프 간선 색칠)
  src/adapters/neis.ts  나이스 개방 자료 해석과 변경 이력 복원
apps/web          Next.js 정적 내보내기
  lib/brand.ts      제품 이름 한 곳
  lib/app.ts        저장 형식, 학사일정 변환, 문구 생성
  lib/neis.ts       나이스 개방 포털 클라이언트
  lib/requests.ts   요청 저장과 승인·반려·게시 상태 전이
  test/             lib 아래 순수 함수 시험
scripts           검사 도구
  check-config.mjs  배포 설정이 서로 어긋났는지
  serve-checked.mjs 배포와 같은 응답 헤더로 띄우기
  smoke.mjs         브라우저 전 과정 점검
```

## 개발

```bash
npm ci              # 잠금 파일 그대로 설치
npm run check       # 배포 설정이 서로 맞는지
npm run typecheck   # 엔진과 웹 앱 타입 검사
npm test            # 엔진과 웹 도메인 단위 테스트
npm run build       # 웹 정적 빌드 (결과는 apps/web/out)
npm run demo        # 엔진 CLI 데모
```

배포와 같은 조건으로 확인하려면 응답 헤더를 씌워 띄운다.

```bash
npm run serve       # vercel.json 의 헤더를 그대로 적용해 3100 포트로 띄운다
npm run smoke       # 다른 창에서 브라우저 전 과정 점검
```

푸시와 풀 리퀘스트마다 GitHub Actions 가 위 전부를 다시 돌린다.
자세한 구성은 [04-operations.md](04-operations.md) 에 있다.
